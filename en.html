Complete Koha Installation and Configuration Manual

A structured guide focused on operational stability: meticulous OS preparation across 5 scenarios, an automated script with automatic backups to Google Drive, first web access, database restoration, and publishing via Cloudflare Tunnel.

1. What is Koha and how it works

Koha is the world's most widely used open-source Integrated Library System (ILS). It operates on the LAMP stack (Linux, Apache, MariaDB, and Perl), functioning as a centralized enterprise server.

Universal Browser Access

The system is hosted on a single server machine. Staff and patrons use Koha directly through a web browser (Google Chrome, Firefox, Edge), with no need to install programs on circulation or OPAC computers.

Koha strictly operates through two standardized network ports:

  • Port 8080 (Staff / Administrative Interface): Restricted panel for librarians and clerks. Used for bibliographic cataloging in MARC21 format, circulation control (check-outs and check-ins), patron management, fine management, and generating SQL reports.
  • Port 80 (OPAC / Online Public Access Catalog): The public page for patrons. It allows users to search the library's collection, check shelf availability, renew loans, and place holds online.

Library Network Management: A single installation can manage multiple physical branches (like a main library and several neighborhood branches or school reading rooms). All share the same catalog while maintaining individual inventory control and circulation rules.

2. Choosing the Hosting and Preparing the Operating System

Koha was natively designed to run on Linux (Debian or Ubuntu). How you reach the command line depends entirely on the installation method chosen below. Strictly follow only the scenario you have chosen:

Scenario 1: Dedicated Physical Server (Ubuntu Server)

A clean installation on a physical computer in the library with no previous operating system.

  • Download the ISO Image: Download the official Ubuntu Server LTS image.
  • Create a Bootable USB Drive: Download and install BalenaEtcher. Connect a USB drive of at least 4GB, open BalenaEtcher, click Flash from file, select the downloaded ISO, choose your USB drive, and click Flash!.
  • Motherboard BIOS Adjustments: Connect the computer to the router via an ethernet cable. Turn on the PC while pressing the BIOS access key (Del, F2, F10, or F12) and configure:
    • Secure Boot: Change to Disabled.
    • SATA Mode: Ensure it is set to AHCI (if the motherboard has this option).
    • Restore on AC Power Loss / AC Back: Change to Power On (makes the server turn on by itself if the power goes out and comes back).
    • Fast Boot: Change to Disabled.
    • Halt On: Change to No Errors (prevents the BIOS from stopping the boot due to a missing keyboard).
  • Ubuntu Server Installation: In the BIOS boot tab, select the USB drive. During the installer:
    • Select the language and leave the network on automatic DHCP (via cable).
    • Partitioning: Choose Use an entire disk.
    • Set the server name, username, and a strong password (write this data down!).
    • Critical Attention: On the additional packages screen, check the "Install OpenSSH server" option using the spacebar. Without this, you will not be able to access the machine remotely.
  • Once finished, restart the machine, remove the USB drive, and log in with your username and password. Identify the machine's IP address with the ip a command (as explained in Section 3). Since this machine has no graphical interface, all management will be done via SSH from your desktop computer's PowerShell.

Scenario 2: Cloud Server / VPS

Installation on a cloud provider (DigitalOcean, Hetzner, AWS, Hostinger, etc.).

  • Create an account with the chosen company and set up the payment method.
  • Click on Create Instance (or Create Droplet).
  • Operating System: Choose Ubuntu Server (recent LTS version: 22.04 or 24.04).
  • Hardware Plan (Mandatory): Select a plan that offers at least 4GB of RAM and 2 vCPUs. Plans with 1GB or 2GB will crash during search indexing.
  • Authentication: Choose root password authentication or add your public SSH key.
  • Finish the creation. In a few seconds, the VPS panel will provide a public IP address and the login user (usually root or ubuntu). Access will be done remotely from your terminal or PowerShell via SSH.

Scenario 3: Computer with Graphical Linux (Linux Mint or Ubuntu Desktop)

Installation on a machine with a visual desktop for direct use on the computer.

  • Download the ISO:
    • Option 1 (Recommended for beginners): Download Linux Mint (Cinnamon Edition).
    • Option 2: Download Ubuntu Desktop.
  • Flash the ISO to the USB drive using BalenaEtcher in the same way explained in Scenario 1.
  • Disable Secure Boot in the computer's BIOS and start the system from the USB drive.
  • On the installer's desktop, double-click the "Install Linux Mint" (or Install Ubuntu) icon. The wizard is entirely visual: choose your time zone, keyboard layout, create your username and password.
  • Complete the installation and restart the PC.
  • Operational Advantage of this Scenario: You DO NOT need to use SSH! Open the system's native terminal by pressing Ctrl + Alt + T and run the commands directly in it. All backup file transfers can be done simply by dragging folders through the visual interface.

Scenario 4: Windows using VirtualBox

Running Ubuntu Server inside a virtual machine on Windows.

  • Enable Virtualization: Restart Windows, enter the BIOS, and enable virtualization support: look for Intel Virtualization Technology (VT-x) or SVM Mode (AMD) and set it to Enabled. Without this, VirtualBox will not create 64-bit systems.
  • Required Downloads: Download and install VirtualBox and download the Ubuntu Server LTS ISO.
  • Creating the Virtual Machine in VirtualBox:
    • Open VirtualBox and click the New button. Name: Type Koha-Server.
    • ISO Image: Point to the Ubuntu Server ISO file.
    • CRITICAL ATTENTION (Skip Unattended Installation Checkbox): On the creation screen, check the "Skip Unattended Installation" box. If "Proceed with Unattended Installation" appears, DO NOT LEAVE IT SELECTED. If you allow it, VirtualBox will create a random user and skip OpenSSH, locking you out of the system!
  • Hardware Resources: Base Memory (RAM): at least 4096 MB (4 GB). Processors: allocate at least 2 CPUs. Hard Disk: at least 25 GB.
  • Network Configuration (Crucial for working on the local network):
    • Go to Settings > Network.
    • In the Attached to: field, change from "NAT" to Bridged Adapter.
    • In the Name field, select your computer's network card (Wi-Fi or Ethernet).
    • Why is this mandatory? In NAT mode, Koha is isolated. In Bridge mode, your router assigns a real IP to the virtual machine, allowing the local network to access Koha on ports 8080 and 80.
  • Start the VM and follow the manual Ubuntu Server installation normally, remembering to check the OpenSSH package.

Scenario 5: Windows using WSL2

The lightest way to run the integrated Linux kernel directly inside Windows 10 or 11.

  • Enable virtualization (VT-x / AMD-V) in your motherboard's BIOS.
  • In the Windows Start menu, search for Turn Windows features on or off and check: Windows Subsystem for Linux and Virtual Machine Platform. Click OK and restart.
  • In the Start menu, look for PowerShell, right-click, and select Run as Administrator. Type the command below and press Enter:
    PowerShell (Administrator)
    wsl --install -d Ubuntu
  • Wait for the download and installation. Upon restarting, the black Ubuntu window will open asking you to create a user and password (write this data down).
  • Pin the Ubuntu shortcut to the taskbar.
  • Operational Advantage of this Scenario: You DO NOT need SSH! Just open the Ubuntu shortcut and paste the commands directly into it. For Koha to work on the network, simply keep this window open and minimized.

3. IP Identification and Terminal Access

Who needs and who DOES NOT need SSH?

Scenarios 3 and 5 (Graphical Linux / WSL2): You are working directly on the machine. You DO NOT need SSH. Open the terminal on your screen (Ctrl + Alt + T on Linux or the Ubuntu shortcut on Windows) and execute all commands through it.

Scenarios 1, 2, and 4 (Physical Server / VPS / VirtualBox): The server is running in text mode without its own monitor or in the background. You need to connect to it through another computer's PowerShell using SSH.

How to identify the Server's IP (Scenarios 1, 2, and 4)

In the Linux terminal, run the command:

Linux Terminal
ip a

How to find your IP in the output: Look for the main network interface (e.g., eth0, enp3s0, or wlan0). Ignore the lo interface. On the line starting with inet, the number before the slash is your IP (e.g., if it shows inet 192.168.1.50/24, the IP is 192.168.1.50). If you are on a VPS, the IP is the public address provided by the panel.

Remote Connection via PowerShell (Only Scenarios 1, 2, and 4)

On the Windows computer you use for work, open PowerShell and type the command below (replace username with the username you created on the server and serverip with the real IP you discovered):

PowerShell
ssh -L 53682:127.0.0.1:53682 username@serverip

Why do we use "-L 53682:127.0.0.1:53682"? This makes PowerShell forward the Google Drive authentication port to your local browser. When the installer asks to authorize the backup, you will be able to approve the account on your own computer without a connection refused error.

4. Automated System Installation

With the terminal open (whether locally on Linux Mint/WSL or via SSH in PowerShell), obtain administrator privileges:

Terminal
sudo -i

Type the Linux user's password. Then, copy and paste the entire line below to trigger the remote automated installer:

Linux Terminal (Root) - Installation Script
bash <(curl -s https://raw.githubusercontent.com/PauloFBaldiFH/Tutorial-Koha/main/instalar.sh)

5. Completing the Web Installer in the Browser

In step 10 of the script, the terminal will display the provisional credentials and will keep checking every 10 seconds until you complete the wizard. Leave the terminal window open in the background!

Open your web browser and go to:

  • Scenarios 1, 2, and 4 (Physical Server / VPS / VirtualBox): Type http://serverip:8080 (example: http://192.168.1.50:8080).
  • Scenarios 3 and 5 (Linux Mint / WSL2): Type directly http://localhost:8080.

Follow the steps exactly in this sequence:

  1. Step 1 of 9 (Provisional Login): The initial screen will appear. In the User field type koha_library. In the Password field, paste the provisional password generated in the terminal.
  2. Step 2 of 9 (Language): Select the option English (en) and click Continue.
  3. Step 3 of 9 (Modules and MARC Format): The wizard will display the Perl modules (all OK). Proceed and choose MARC21 (international standard).
  4. Step 4 of 9 (Optional Settings): Keep the MARC21 frameworks checked, but uncheck all boxes mentioning sample data ("sample patrons", "sample libraries", "sample items"). This prevents the database from being populated with dummy records.
  5. Step 5 of 9 (Library Setup): Library Code: enter a short acronym (e.g., BPM, CENTRAL). Library Name: the full official name.
  6. Step 6 of 9 (Patron Category): Category Code: type STAFF. Description: type Administration. Category Type: select Staff.
  7. Step 7 of 9 (Superlibrarian): Fill in the management account details. Surname/First Name: Your name. Card Number: 1. Username: your everyday login. Password: Create a strong, secure password and write it down.
  8. Step 8 of 9 (Item Type): Item Type Code: type BK. Description: type Book.
  9. Step 9 of 9 (Circulation Rules): Total loans allowed: 3 to 5 items. Loan period: 14 days. Renewals allowed: 2 renewals.
Final Attention: When clicking the button to complete the wizard, return immediately to your terminal window. It will detect the user creation, reindex the data, and successfully finish the installation!

6. Restoring a Previous Backup (Optional)

If you already have a database file extracted from a previous Koha installation, follow these steps to restore your collection:

1. File Name and Format

The file must be an uncompressed SQL dump (with a .sql extension) and must be renamed exactly to koha_library.sql. If it is compressed as .sql.gz or .tar.gz, use 7-Zip or WinRAR to extract the SQL file from within it.

2. How to place the file on the server in each Scenario

If you are on Linux Mint / Ubuntu Desktop (Scenario 3):

Open the visual Linux file manager, go to your personal folder (Home) and simply paste the koha_library.sql file there.

If you are on Windows using WSL2 (Scenario 5):

You can copy the file directly through Windows Explorer! Open Windows File Explorer and type in the address bar (replace username with your Ubuntu user):

\\wsl$\Ubuntu\home\username\

Paste the koha_library.sql file directly into that folder.
Alternatively, if you placed the file in your Windows C:\ drive, type in the WSL2 terminal:

WSL2 Terminal
cp /mnt/c/koha_library.sql ~/koha_library.sql

If you are on a Physical Server, VPS, or VirtualBox (Scenarios 1, 2, and 4):

Place the file in the root of your local Windows C:\ drive (so the exact path is C:\koha_library.sql). Open a new PowerShell window (without being connected via SSH) and type the command below (replace username and serverip):

PowerShell (Local)
scp "C:\koha_library.sql" username@serverip:/home/username/

3. Executing the Restoration on the Server

In the Linux terminal as root (sudo -i), run this remote script. It recreates the database, imports the old dump, applies schema updates, and rebuilds the indexes. Remember at the end of the installation to copy the Rclone link into the browser to enable automatic backups to Google Drive.

Linux Terminal (Root) - Restoration Script
bash <(curl -s https://raw.githubusercontent.com/PauloFBaldiFH/Tutorial-Koha/main/restaurar.sh)

7. Publishing Koha on the Internet (Cloudflare Tunnel)

Cloudflare Tunnel is the safest way to expose Koha to the internet. It eliminates the need to open ports on the library's modem or router, hides the server's real IP from attacks, and automatically provides an SSL certificate (HTTPS).

Step 1: Institutional Domain or Free Subdomain

To put the catalog on the web, a domain address is required:

  • Custom Domain (Recommended): Register an institutional domain (e.g., municipallibrary.org) directly in the Cloudflare dashboard (average cost $10 to $15 per year).
  • Free Subdomain (Zero Cost): Use a free DigitalPlat subdomain by following the procedure below:
    1. Go to domain.digitalplat.org and create a free account.
    2. In the left side menu, click on Register a domain and select Domain registration.
    3. Type the chosen name for the library and choose one of the 4 available extensions: .dpdns.org, .us.kg, .qzz.io, or .xx.kg.
    4. Click Check availability. If the name is available, the screen will display the name server fields: Name Server 1 to 4. Keep this page open.
    5. In another browser tab, log into the Cloudflare dashboard and click Add a site.
    6. Paste the full name of the subdomain created on DigitalPlat (e.g., municipallibrary.dpdns.org) and click continue.
    7. On the plans screen, scroll to the bottom, select the Free Plan and continue.
    8. Cloudflare will provide two authoritative name servers (e.g., ns1.cloudflare.com and ns2.cloudflare.com). Copy the first address.
    9. Go back to the DigitalPlat tab, paste the first address into the Name Server 1 field and the second into the Name Server 2 field. Save the changes on DigitalPlat.
    10. Back on Cloudflare, click the Done, check nameservers button.
DNS Propagation Time: Nameserver delegation on free subdomains usually takes between 15 minutes and up to 1 hour to propagate across the internet. If Cloudflare displays a warning stating that the servers have not yet been detected, do not delete the domain: wait a few minutes and click "Check nameservers now" again.

Step 2: Creating the Cloudflare Tunnel

  1. In the Cloudflare side panel, navigate to: Zero Trust > Networks > Tunnels.
  2. Click on Add a tunnel, choose the Cloudflare Managed option, and define an identification name (e.g., koha-server).
  3. On the connector installation screen, click the Debian option and select the 64-bit architecture.
  4. The panel will display two commands in a black box: The first downloads the official cloudflared connector package. The second installs the service and links the tunnel's unique authentication token.
  5. Copy and execute both commands in the Linux terminal as root. The service will start immediately in the background.

Step 3: Mapping the Staff and OPAC Routes

In the tunnel panel, click the Public Hostnames tab. You must register two routes by clicking the Add a public hostname button:

Purpose Subdomain Domain Path Service Type Local URL
Staff (Administration) adm Your registered domain Leave blank HTTP localhost:8080
OPAC (Public / Patron) Leave blank Your registered domain Leave blank HTTP localhost:80

With this configuration, librarians will access the system via https://adm.yourdomain.org and patrons will search the catalog via https://yourdomain.org.

Step 4: Shielding against Scrapers and AI Bots

Public catalogs suffer continuous scans from AI training bots, generating mass requests that can overload the system. To protect the server:

  • In the Cloudflare panel, open your domain settings and click Security > Bots.
  • Toggle the Bot Fight Mode switch on.
  • In the AI security tab, enable the Block AI scrapers and crawlers option.
  • If the library experiences sudden slowness due to unusual traffic, temporarily enable Under Attack Mode on the domain's home page to require a security challenge from visitors.

Step 5: Google Indexing and Koha Base URLs

  1. Access Google Search Console with your institutional account.
  2. Select the verification method by URL prefix or Domain, enter your OPAC address, and copy the TXT code generated by Google.
  3. In the Cloudflare panel, go to DNS > Records and click Add record:
    • Type: Choose TXT
    • Name: Type @ (represents the root domain).
    • Content: Paste the code generated by Google and save. Return to Google and verify ownership.
  4. In the Koha Staff panel (as administrator), go to: Koha administration > Global system preferences:
    • Search for OpacBaseUrl: Enter the full public HTTPS URL of the catalog (e.g., https://municipallibrary.dpdns.org).
    • Search for StaffBaseUrl: Enter the full public HTTPS URL of the administration (e.g., https://adm.municipallibrary.dpdns.org).
    • Search for LibraryName: Enter the official name of the library that will appear in the titles of Google search results.
    • Search for OpacMetaRobots: Make sure to keep any option that blocks search robots (like noindex) disabled, allowing Google to read and catalog.
