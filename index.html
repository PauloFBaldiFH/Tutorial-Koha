Manual Completo de Instalação e Configuração do Koha

Guia estruturado com foco em estabilidade operacional: preparação minuciosa do sistema operacional em 5 cenários, script automatizado com Elasticsearch, primeiro acesso web, restauração de banco de dados e publicação via Cloudflare Tunnel.

1. O que é e como funciona o Koha

O Koha é o sistema integrado de gestão de bibliotecas (ILS) de código aberto mais utilizado no mundo. Ele opera sobre a stack LAMP (Linux, Apache, MariaDB e Perl), funcionando como um servidor central corporativo.

Acesso Universal por Navegador: O sistema fica hospedado em uma única máquina servidora. Funcionários e leitores utilizam o Koha diretamente pelo navegador web (Google Chrome, Firefox, Edge), sem necessidade de instalar programas nos computadores de atendimento ou consulta.

O Koha opera obrigatoriamente através de duas portas de rede padronizadas:

  • Porta 8080 (Staff / Interface Administrativa): Painel restrito dos bibliotecários e atendentes. Utilizada para catalogação bibliográfica no padrão MARC21, controle de circulação (empréstimos e devoluções), cadastro de usuários, gestão de multas e geração de relatórios SQL.
  • Porta 80 (OPAC / Catálogo Público): Página pública voltada aos leitores. Permite consultar o acervo da biblioteca, checar disponibilidade nas estantes, renovar prazos e reservar títulos pela internet.

Gestão de Redes de Bibliotecas: Uma única instalação permite administrar múltiplas unidades físicas (como uma biblioteca central e várias filiais de bairros ou salas de leitura escolares). Todas compartilham o mesmo catálogo, mantendo o controle de estoque e regras de circulação individualizados.

2. Escolhendo a Hospedagem e Preparando o Sistema Operacional

O Koha foi concebido nativamente para rodar sobre Linux (Debian ou Ubuntu). A forma como você chega à linha de comando depende exclusivamente do método de instalação escolhido abaixo. Siga rigorosamente apenas o cenário que você escolheu:

Cenário 1

Servidor Físico Dedicado (Ubuntu Server)

Instalação limpa em um computador físico da biblioteca sem sistema operacional prévio.

  1. Download da Imagem ISO: Baixe a imagem oficial do Ubuntu Server: Download Ubuntu Server LTS.
  2. Criação do Pendrive Bootável: Baixe e instale o BalenaEtcher. Conecte um pendrive de no mínimo 4GB, abra o BalenaEtcher, clique em Flash from file, selecione o arquivo ISO baixado, selecione seu pendrive e clique em Flash!.
  3. Ajustes na BIOS da Placa-Mãe: Conecte o computador via cabo de rede no roteador. Ligue o PC pressionando a tecla de acesso à BIOS (Del, F2, F10 ou F12) e configure:
    • Secure Boot: Mude para Disabled.
    • SATA Mode: Garanta que esteja em AHCI (se a placa mãe tiver essa opção).
    • Restore on AC Power Loss / AC Back: Mude para Power On (faz o servidor ligar sozinho se a luz cair e voltar).
    • Fast Boot: Mude para Disabled.
    • Halt On: Mude para No Errors (impede que a BIOS trave o boot por falta de teclado conectado).
  4. Instalação do Ubuntu Server: Na aba de boot da BIOS, selecione o pendrive. Durante o instalador:
    • Selecione o idioma e deixe a rede em DHCP automático (via cabo).
    • Particionamento: Escolha Use an entire disk (usar o disco inteiro).
    • Defina o nome do servidor, o nome de usuário e uma senha forte (anote esses dados!).
    • Atenção Crítica: Na tela de pacotes adicionais, marque com a tecla de espaço a opção Install OpenSSH server. Sem isso, você não conseguirá acessar a máquina remotamente.
  5. Ao terminar, reinicie a máquina, retire o pendrive e faça login com seu usuário e senha.
  6. Identifique o IP da máquina com o comando ip a (conforme explicado na Seção 3). Como esta máquina não tem interface gráfica, todo o gerenciamento será feito via SSH pelo PowerShell do seu computador de mesa.
Cenário 2

Servidor em Nuvem / VPS

Instalação em um provedor de nuvem (DigitalOcean, Hetzner, AWS, Hostinger, etc.).

  1. Crie uma conta na empresa escolhida e acerte o método de pagamento.
  2. Clique em Create Instance (ou Create Droplet).
  3. Sistema Operacional: Escolha Ubuntu Server (versão LTS recente: 22.04 ou 24.04).
  4. Plano de Hardware (Obrigatório): Selecione um plano que ofereça no mínimo 4GB de RAM e 2 vCPUs. Planos com 1GB ou 2GB travarão durante a indexação de buscas do Elasticsearch.
  5. Autenticação: Escolha autenticação por senha root ou adicione sua chave SSH pública.
  6. Finalize a criação. Em poucos segundos o painel da VPS fornecerá um Endereço de IP público e o usuário de login (normalmente root ou ubuntu).
  7. O acesso será feito remotamente a partir do seu terminal ou PowerShell via SSH.
Cenário 3

Computador com Linux Gráfico (Linux Mint ou Ubuntu Desktop)

Instalação em uma máquina com área de trabalho visual para uso direto no computador.

  1. Download da ISO:
    • Opção 1 (Recomendada para iniciantes): Download Linux Mint (Cinnamon Edition).
    • Opção 2: Download Ubuntu Desktop.
  2. Grave a ISO no pendrive utilizando o BalenaEtcher da mesma forma explicada no Cenário 1.
  3. Desative o Secure Boot na BIOS do computador e inicie o sistema pelo pendrive.
  4. Na área de trabalho do instalador, dê dois cliques no ícone "Install Linux Mint" (ou Install Ubuntu). O assistente é totalmente visual em português: escolha seu fuso horário, layout do teclado, crie seu nome de usuário e senha.
  5. Conclua a instalação e reinicie o PC.
  6. Vantagem Operacional deste Cenário: Você NÃO precisa usar SSH! Abra o terminal nativo do sistema pressionando as teclas Ctrl + Alt + T e execute os comandos diretamente nele. Toda transferência de arquivos de backup poderá ser feita simplesmente arrastando pastas pela interface visual.
Cenário 4

Windows usando VirtualBox

Execução do Ubuntu Server dentro de uma máquina virtual no Windows.

  1. Ativação de Virtualização: Reinicie o Windows, entre na BIOS e ative o suporte a virtualização: procure por Intel Virtualization Technology (VT-x) ou SVM Mode (AMD) e marque como Enabled. Sem isso, o VirtualBox não criará sistemas de 64 bits.
  2. Downloads Necessários:
    • Baixe e instale o VirtualBox: Download Oracle VM VirtualBox.
    • Baixe a ISO do Ubuntu Server: Download Ubuntu Server LTS.
  3. Criação da Máquina Virtual no VirtualBox:
    • Abra o VirtualBox e clique no botão Novo (New).
    • Nome: Digite Koha-Server.
    • Imagem ISO: Clique na seta, escolha Outro... e aponte para o arquivo ISO do Ubuntu Server que você baixou.
    • ATENÇÃO CRÍTICA (Checkbox de Instalação Desatendida): Na tela de criação do VirtualBox existe a opção sobre instalação desatendida. Marque a caixa "Pular Instalação Desatendida" (Skip Unattended Installation). Se na sua versão do VirtualBox aparecer a caixa "Proceed with Unattended Installation", NÃO A DEIXE SELECIONADA. Se você permitir a instalação desatendida, o VirtualBox criará um usuário padrão aleatório e ignorará a instalação manual do OpenSSH, trancando você fora do sistema!
  4. Recursos de Hardware:
    • Memória Base (RAM): Defina no mínimo 4096 MB (4 GB).
    • Processadores: Aloque ao menos 2 CPUs.
    • Disco Rígido: Crie um disco virtual de pelo menos 25 GB.
  5. Configuração de Rede (Crucial para funcionar na rede local):
    • Com a máquina criada, clique nela e vá em Configurações > Rede.
    • No campo Conectado a:, troque de "NAT" para Placa em modo Bridge (Bridged Adapter).
    • No campo Nome, selecione a placa de rede do seu computador (sua placa Wi-Fi ou Ethernet conectada à internet).
    • Por que isso é obrigatório? No modo NAT, o Koha fica isolado dentro do Windows. No modo Bridge, seu roteador atribui um IP real para a máquina virtual, permitindo que qualquer computador ou celular da biblioteca acesse o Koha nas portas 8080 e 80.
  6. Inicie a VM no VirtualBox e siga a instalação manual do Ubuntu Server normalmente, lembrando de marcar o pacote OpenSSH na tela de utilitários de rede.
Cenário 5

Windows usando WSL2

A forma mais leve de rodar o kernel Linux integrado diretamente dentro do Windows 10 ou 11.

  1. Ative a virtualização (VT-x / AMD-V) na BIOS da sua placa-mãe.
  2. No menu Iniciar do Windows, pesquise por Ativar ou desativar recursos do Windows e marque as duas opções:
    • Subsistema do Windows para Linux
    • Plataforma de Máquina Virtual
    Clique em OK e reinicie o computador se for solicitado.
  3. No menu Iniciar, procure por PowerShell, clique com o botão direito e selecione Executar como Administrador.
  4. Digite o comando abaixo e tecle Enter:
PowerShell (Administrador) 
wsl --install -d Ubuntu
  1. Aguarde o download e instalação. Ao concluir, reinicie o computador se o sistema pedir.
  2. Ao reiniciar, a janela preta do terminal do Ubuntu abrirá automaticamente solicitando que você crie um usuário e uma senha do Linux (anote esses dados).
  3. No menu Iniciar do Windows, pesquise por Ubuntu, clique com o botão direito e escolha Fixar na barra de tarefas.
  4. Vantagem Operacional deste Cenário: Você NÃO precisa de SSH! Basta abrir o atalho do Ubuntu na barra de tarefas e colar os comandos diretamente nele. Para que o Koha continue funcionando, basta manter essa janela aberta minimizada.

3. Identificação de IP e Acesso ao Terminal

Quem precisa e quem NÃO precisa de SSH?

Regra Clara de Acesso:
• Cenários 3 e 5 (Linux Gráfico / WSL2): Você está trabalhando diretamente na máquina. NÃO precisa de SSH. Abra o terminal na sua tela (Ctrl + Alt + T no Linux ou atalho do Ubuntu no Windows) e execute todos os comandos por ele.
• Cenários 1, 2 e 4 (Servidor Físico / VPS / VirtualBox): O servidor está rodando em modo texto sem monitor próprio ou em segundo plano. Você precisa conectar nele através do PowerShell de outro computador usando SSH.

Como identificar o IP do Servidor (Cenários 1, 2 e 4)

No terminal do Linux, execute o comando:

Terminal Linux 
ip a
Como localizar seu IP na resposta:
Procure pela interface de rede principal (ex: eth0, enp3s0 ou wlan0). Ignore a interface lo. Na linha que começa com inet, o número antes da barra é o seu IP (ex: se aparecer inet 192.168.1.50/24, o IP é 192.168.1.50). Se estiver em uma VPS, o IP é o endereço público fornecido pelo painel do provedor.

Conexão Remota via PowerShell (Apenas Cenários 1, 2 e 4)

No computador Windows que você usa para trabalhar, abra o PowerShell e digite o comando abaixo (lembre-se de substituir nomedousuario pelo nome do usuário que você criou no servidor e ipdoservidor pelo IP real que você descobriu no comando ip a):

PowerShell 
ssh -L 53682:127.0.0.1:53682 nomedousuario@ipdoservidor
Por que usamos "-L 53682:127.0.0.1:53682"? Isso faz o PowerShell encaminhar a porta de autenticação do Google Drive para o seu navegador local. Quando o instalador pedir para autorizar o backup, você conseguirá aprovar a conta no seu próprio computador sem erro de conexão recusada.

4. Instalação Automatizada do Sistema

Com o terminal aberto (seja local no Linux Mint/WSL ou via SSH no PowerShell), obtenha privilégios de administrador:

Terminal 
sudo -i

Digite a senha do usuário do Linux. Em seguida, copie e cole o bloco completo abaixo:

script_instalacao_koha.sh 
#!/bin/bash
set -e

if [ "$EUID" -ne 0 ]; then
  echo "ERRO: Execute este script como root ('sudo -i')."
  exit 1
fi

REAL_USER="${SUDO_USER:-$USER}"
REAL_HOME=$(getent passwd "$REAL_USER" | cut -d: -f6)
[ -z "$REAL_HOME" ] && REAL_HOME="/home/$REAL_USER"

echo ">>> Configuração de Fuso Horário..."
echo "Por favor, selecione sua região e fuso horário na tela que vai aparecer."
dpkg-reconfigure tzdata
timedatectl set-ntp true

export DEBIAN_FRONTEND=noninteractive

# 1. SWAP PREVENTIVO (4GB)
echo ">>> Verificando SWAP..."
if [ "$(swapon --show | wc -l)" -le 1 ]; then
  fallocate -l 4G /swapfile || dd if=/dev/zero of=/swapfile bs=1M count=4096
  chmod 600 /swapfile
  mkswap /swapfile
  swapon /swapfile
  echo '/swapfile none swap sw 0 0' >> /etc/fstab
fi

# 2. DEPENDÊNCIAS E REPOSITÓRIOS OFICIAIS
echo ">>> Instalando dependências e repositórios..."
apt update && apt upgrade -y
apt install -y nano curl wget gpg ufw software-properties-common default-jre-headless \
              libapache2-mod-security2 fail2ban postfix libsasl2-modules glabels \
              at rclone avahi-daemon memcached

systemctl enable --now avahi-daemon
systemctl enable --now fail2ban

wget -qO - https://debian.koha-community.org/koha/gpg.asc | gpg --dearmor --yes -o /usr/share/keyrings/koha-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/koha-keyring.gpg] https://debian.koha-community.org/koha oldstable main" > /etc/apt/sources.list.d/koha.list

wget -qO - https://artifacts.elastic.co/GPG-KEY-elasticsearch | gpg --dearmor --yes -o /usr/share/keyrings/elasticsearch-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/elasticsearch-keyring.gpg] https://artifacts.elastic.co/packages/7.x/apt stable main" > /etc/apt/sources.list.d/elastic-7.x.list

apt update
apt install -y mariadb-server elasticsearch koha-common koha-elasticsearch

# 3. ELASTICSEARCH E PLUGIN ICU
echo ">>> Configurando Elasticsearch..."
mkdir -p /etc/elasticsearch/jvm.options.d
cat << 'EOF' > /etc/elasticsearch/jvm.options.d/koha.options
-Xms1g
-Xmx1g
EOF

/usr/share/elasticsearch/bin/elasticsearch-plugin install --batch analysis-icu 2>/dev/null || true
systemctl daemon-reload
systemctl enable --now elasticsearch

until curl -s http://localhost:9200 >/dev/null; do sleep 1; done

# 4. REDE, APACHE E MEMCACHED
echo ">>> Configurando Apache, portas e memcached..."
sed -i 's/^INTRAPORT=.*/INTRAPORT="8080"/' /etc/koha/koha-sites.conf
sed -i 's/^OPACPORT=.*/OPACPORT="80"/' /etc/koha/koha-sites.conf
sed -i 's/^#*MEMCACHED_SERVERS=.*/MEMCACHED_SERVERS="127.0.0.1:11211"/' /etc/koha/koha-sites.conf
sed -i 's/^#*MEMCACHED_PREFIX=.*/MEMCACHED_PREFIX="koha_"/' /etc/koha/koha-sites.conf

a2enmod rewrite cgi deflate headers proxy_http
grep -q "^Listen 8080" /etc/apache2/ports.conf || sed -i '/Listen 80/a Listen 8080' /etc/apache2/ports.conf
systemctl restart apache2

# --- LIMPEZA DE TENTATIVAS ANTERIORES (evita "Duplicate entry" no Web Installer) ---
echo ">>> Removendo qualquer instância/banco anterior chamado 'library'..."
koha-remove library 2>/dev/null || true
mysql -e "DROP DATABASE IF EXISTS koha_library;" 2>/dev/null || true
mysql -e "DROP USER IF EXISTS 'koha_library'@'localhost';" 2>/dev/null || true
curl -s -X DELETE 'localhost:9200/koha_library_biblios' >/dev/null 2>&1 || true
curl -s -X DELETE 'localhost:9200/koha_library_authorities' >/dev/null 2>&1 || true
rm -rf /etc/koha/sites/library

# 5. CRIAÇÃO DA INSTÂNCIA (limpa, SEM Elasticsearch por enquanto)
echo ">>> Criando instância 'library' (Zebra por enquanto, ES vem depois)..."
koha-create --create-db library

systemctl stop koha-zebra-daemon@library 2>/dev/null || true
systemctl disable koha-zebra-daemon@library 2>/dev/null || true
koha-zebra --stop library 2>/dev/null || true
koha-zebra --disable library 2>/dev/null || true

sed -i 's/__MEMCACHED_SERVERS__/127.0.0.1:11211/g' /etc/koha/sites/library/koha-conf.xml
sed -i 's/__MEMCACHED_PREFIX__/koha_library:/g' /etc/koha/sites/library/koha-conf.xml

# --- Permissões dos logs do indexador ES (evita "Permission denied" no daemon) ---
mkdir -p /var/log/koha/library
touch /var/log/koha/library/es-indexer-error.log
touch /var/log/koha/library/es-indexer-output.log
chown library-koha:library-koha /var/log/koha/library/es-indexer-error.log /var/log/koha/library/es-indexer-output.log
chmod 664 /var/log/koha/library/es-indexer-error.log /var/log/koha/library/es-indexer-output.log

a2dissite 000-default 2>/dev/null || true
a2ensite library
systemctl restart apache2
systemctl restart memcached

koha-translate --install pt-BR
koha-plack --enable library
koha-plack --start library
systemctl restart koha-common

# 6. ROTINAS DE BACKUP E CRON
echo ">>> Configurando backup e crontab..."
ARQUIVO_CONF="/etc/koha/sites/library/koha-conf.xml"
DB_PASS=$(grep -oP '(?<=<pass>)[^<]+' "$ARQUIVO_CONF" | head -n 1)
DB_USER="koha_library"

mkdir -p "$REAL_HOME/logs" "/var/backups"
chown -R "$REAL_USER":"$REAL_USER" "$REAL_HOME/logs" 2>/dev/null || true

cat << EOF > "$REAL_HOME/backup_aut.sh"
#!/bin/bash
set -o pipefail
DATA=\$(date +%Y-%m-%d_%Hh%M)
DIR_BACKUP="/var/backups"
DIR_LOG="$REAL_HOME/logs"

mkdir -p "\$DIR_BACKUP" "\$DIR_LOG"
LOG_FILE="\$DIR_LOG/backup_\$DATA.log"

echo "Iniciando backup em \$DATA" >> "\$LOG_FILE"
mysqldump -u"$DB_USER" -p'$DB_PASS' "koha_library" | gzip > "\$DIR_BACKUP/koha_library_\$DATA.sql.gz"

if [ \$? -ne 0 ]; then
  echo "ERRO: Falha ao gerar o dump do banco!" >> "\$LOG_FILE"
  exit 1
fi

/usr/bin/rclone --config /root/.config/rclone/rclone.conf move "\$DIR_BACKUP/koha_library_\$DATA.sql.gz" gdrive:Backup_Koha >> "\$LOG_FILE" 2>&1
find "\$DIR_BACKUP" -name "koha_library_*.sql.gz" -mtime +7 -exec rm {} \;
echo "Finalizado em \$(date)" >> "\$LOG_FILE"
EOF

chmod +x "$REAL_HOME/backup_aut.sh"
chown "$REAL_USER":"$REAL_USER" "$REAL_HOME/backup_aut.sh" 2>/dev/null || true
ln -sf "$REAL_HOME/backup_aut.sh" /root/backup_aut.sh

cat << EOF > /tmp/koha_cron
30 0 * * * /usr/bin/journalctl --vacuum-time=14d
0 2 * * 1 /usr/bin/apt update -y && /usr/bin/apt upgrade -y && /usr/bin/apt autoremove -y && /usr/bin/apt clean
0 1 5 * * /usr/bin/mysqlcheck --check --auto-repair --databases koha_library
0 5 * * * /usr/sbin/koha-plack --restart library
40 17 * * * /bin/bash $REAL_HOME/backup_aut.sh
EOF
crontab /tmp/koha_cron
rm /tmp/koha_cron

# 7. FIREWALL COM TRAVA DE SEGURANÇA
echo ">>> Ativando firewall..."
echo "ufw disable" | at now + 10 minutes
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 8080/tcp
ufw allow 587/tcp
ufw allow 53682/tcp
echo "y" | ufw enable

# 8. MENSAGEM DO SISTEMA
IP_REAL=$(hostname -I | awk '{print $1}')
[ -z "$IP_REAL" ] && IP_REAL="ipdoservidor"

cat << EOF > /etc/issue
Ubuntu \n \l

======================================================================
                 SISTEMA KOHA PRONTO PARA O WEB INSTALLER!
======================================================================
 Enderecos de Acesso:
 - Staff (Adm):  http://${IP_REAL}:8080
 - OPAC (Leitor): http://${IP_REAL}:80
----------------------------------------------------------------------
 Primeiro Acesso / Web Installer:
 - Usuario: $DB_USER
 - Senha:   $DB_PASS
======================================================================

EOF
cp /etc/issue /etc/issue.net
cp /etc/issue /etc/motd

echo ""
echo "======================================================================"
echo " INSTALAÇÃO BASE CONCLUÍDA."
echo " Acesse http://${IP_REAL}:8080 e complete o Web Installer no navegador."
echo " Usuário: $DB_USER  | Senha: $DB_PASS"
echo ""
echo " Crie uma senha forte para o bibliotecário administrador no Web Installer e anote-a."
echo "======================================================================"

# 9. AUTORIZAÇÃO DO GOOGLE DRIVE COM CONFIGURAÇÃO AUTOMÁTICA
echo -e "\n\033[1;33m======================================================================"
echo "          AUTORIZAÇÃO DO GOOGLE DRIVE (RCLONE)                                "
echo "======================================================================\033[0m"
echo "O link abaixo aparecerá em instantes."
echo "Copie o endereço (http://127.0.0.1:53682/...), cole no seu navegador e faça login na sua conta Google:"
echo "----------------------------------------------------------------------"
mkdir -p /root/.config/rclone
RCLONE_TOKEN=$(rclone authorize "drive")

cat << EOF_RCLONE > /root/.config/rclone/rclone.conf
[gdrive]
type = drive
token = $RCLONE_TOKEN
EOF_RCLONE

/usr/bin/rclone --config /root/.config/rclone/rclone.conf mkdir gdrive:Backup_Koha 2>/dev/null || true
echo ">>> Rclone configurado com sucesso e pasta remota vinculada!"

# 10. AGUARDA VOCÊ TERMINAR O WEB INSTALLER
echo ""
echo "======================================================================"
echo " Aguardando você concluir o Web Installer em http://${IP_REAL}:8080 ..."
echo " (verifica a cada 10s; continua sozinho quando detectar que o usuário"
echo " bibliotecário foi criado, ou seja, o wizard chegou ao fim)"
echo "======================================================================"
while true; do
  COUNT=$(mysql -N -e "SELECT COUNT(*) FROM koha_library.borrowers;" 2>/dev/null || echo 0)
  if [ "$COUNT" -gt 0 ] 2>/dev/null; then
        break
  fi
  sleep 10
done
echo ">>> Web Installer concluído. Configurando Elasticsearch agora..."

CONF="/etc/koha/sites/library/koha-conf.xml"
if ! grep -q "<elasticsearch>" "$CONF"; then
  sed -i "/<\/config>/i \\  <elasticsearch>\\n    <server>127.0.0.1:9200</server>\\n    <index_name>koha_library<\/index_name>\\n  </elasticsearch>" "$CONF"
fi

echo ">>> Definindo SearchEngine = Elasticsearch e ativando commit imediato..."
mysql -e "UPDATE koha_library.systempreferences SET value='Elasticsearch' WHERE variable='SearchEngine';"
mysql -e "UPDATE koha_library.systempreferences SET value='1' WHERE variable='ElasticsearchCommitImmediately';"

# --- Permissões dos logs do indexador ES (evita "Permission denied" no daemon) ---
mkdir -p /var/log/koha/library
touch /var/log/koha/library/es-indexer-error.log
touch /var/log/koha/library/es-indexer-output.log
chown library-koha:library-koha /var/log/koha/library/es-indexer-error.log /var/log/koha/library/es-indexer-output.log
chmod 664 /var/log/koha/library/es-indexer-error.log /var/log/koha/library/es-indexer-output.log

echo ">>> Reiniciando serviços para carregar a nova config..."
systemctl restart koha-common
koha-plack --restart library
sleep 3

echo ">>> Apagando índices antigos (se existirem) e reindexando do zero..."
curl -s -X DELETE 'localhost:9200/koha_library_biblios' >/dev/null 2>&1 || true
curl -s -X DELETE 'localhost:9200/koha_library_authorities' >/dev/null 2>&1 || true
koha-elasticsearch --rebuild -d library

echo ">>> Reiniciando serviços mais uma vez..."
systemctl restart koha-common
koha-plack --restart library

echo ">>> Verificando se o daemon de indexação está de pé..."
sleep 3
if ps aux | grep -v grep | grep -q es_indexer_daemon; then
  echo "OK: daemon es_indexer_daemon está rodando."
else
  echo "ATENÇÃO: o daemon não apareceu no ps aux. Confira:"
  echo "  journalctl -u koha-common -n 50 --no-pager | grep -A3 es-indexer"
fi

# CANCELA A TAREFA DO 'AT' PARA MANTER O FIREWALL PERMANENTEMENTE ATIVO
for job in $(atq 2>/dev/null | cut -f1); do
  atrm "$job" 2>/dev/null || true
done

echo ""
echo "======================================================================"
echo " INSTALAÇÃO COMPLETA COM ELASTICSEARCH ATIVO."

Abra seu navegador web e acesse:

Endereço de Acesso ao Instalador:
• Cenários 1, 2 e 4 (Servidor Físico / VPS / VirtualBox): Digite http://ipdoservidor:8080 (substitua ipdoservidor pelo IP real da máquina que você identificou pelo comando ip a, por exemplo: http://192.168.1.50:8080).
• Cenários 3 e 5 (Linux Mint / WSL2): Digite diretamente http://localhost:8080.

Siga os passos exatamente nesta sequência:

Etapa 1 de 9

Login Provisório do Banco de Dados

Aparecerá a tela inicial de autenticação do Koha. No campo Usuário digite koha_library. No campo Senha, cole a senha provisória aleatória impressa no seu terminal pelo script. Clique em Entrar.

Etapa 2 de 9

Seleção do Idioma

O instalador perguntará qual idioma você deseja utilizar para o assistente e para o sistema. Selecione a opção Português do Brasil (pt-BR) e clique em Continuar para o próximo passo.

Etapa 3 de 9

Verificação de Módulos e Formato MARC

O assistente exibirá a lista de módulos do Perl (todos com sinal verde de OK). Prossiga até a tela que solicita o formato bibliográfico: escolha MARC21 (padrão internacional de catalogação) e avance.

Etapa 4 de 9

Configurações Opcionais do Acervo

Aparecerá uma tela com várias opções de dados padrão. Mantenha marcados os frameworks do MARC21, mas desmarque todas as caixas que mencionarem dados de exemplo ("amostras de usuários", "amostras de bibliotecas", "amostras de itens"). Isso impede que o banco seja criado com registros fictícios.

Etapa 5 de 9

Cadastro da Biblioteca Principal

Preencha os dados institucionais:

  • Código da Biblioteca: Uma sigla curta em maiúsculas sem espaços (ex: BPM, CENTRAL ou MATRIZ).
  • Nome da Biblioteca: O nome oficial completo (ex: Biblioteca Pública Municipal).
Etapa 6 de 9

Categoria do Administrador

Defina o perfil de usuário para funcionários técnicos:

  • Código da Categoria: Digite STAFF.
  • Descrição: Digite Administração.
  • Tipo de Categoria: Selecione a opção Funcionário (Staff).
Etapa 7 de 9

Criação do Bibliotecário Administrador (Superlibrarian)

Preencha os dados da conta principal de gerenciamento:

  • Sobrenome e Nome: Seu nome ou cargo institucional.
  • Número de Cartão / Matrícula: Digite 1.
  • Nome de Usuário: O login que você usará no dia a dia.
  • Senha: Crie uma senha forte e segura (combinando letras, números e símbolos) e anote-a. Ela será sua credencial de acesso a todas as configurações do sistema.
Etapa 8 de 9

Categoria Padrão de Exemplar

Cadastre o primeiro formato de acervo que a biblioteca movimentará:

  • Código do Tipo de Exemplar: Digite LIV.
  • Descrição: Digite Livro.
Etapa 9 de 9

Regras Iniciais de Circulação

Defina os parâmetros básicos de empréstimo (que você poderá personalizar detalhadamente depois em Administração > Regras de circulação):

  • Total de empréstimos permitidos: Digite 3 a 5 exemplares.
  • Período de empréstimo: Digite 14 dias.
  • Renovações permitidas: Digite 2 renovações.

Ao clicar no botão final para concluir o assistente, retorne imediatamente à janela do seu terminal: ele detectará automaticamente a criação do usuário, aplicará a injeção do Elasticsearch no XML, reindexará os dados e encerrará a instalação com sucesso!

6. Restauração de Backup Anterior (Opcional)

Se você já possui um arquivo de banco de dados extraído de uma instalação anterior do Koha, siga esta rotina para restaurar seu acervo com reindexação completa no Elasticsearch:

1. Nome e Formato do Arquivo

O arquivo precisa ser um dump SQL descompactado (com extensão .sql) e renomeado obrigatoriamente para koha_library.sql. Se ele estiver compactado como .sql.gz ou .tar.gz, use o 7-Zip ou WinRAR para extrair o arquivo SQL de dentro dele.

2. Como colocar o arquivo no servidor em cada Cenário

Se você está no Linux Mint / Ubuntu Desktop (Cenário 3):

Abra o gerenciador de arquivos visual do Linux, vá na sua pasta pessoal (Home) e simplesmente cole o arquivo koha_library.sql lá dentro.

Se você está no Windows usando WSL2 (Cenário 5):

Você pode copiar o arquivo direto pelo Windows Explorer! Abra o Explorador de Arquivos do Windows e digite na barra de endereços (lembre-se de substituir nomedousuario pelo seu usuário do Ubuntu):

\\wsl$\Ubuntu\home\nomedousuario\

Cole o arquivo koha_library.sql direto nessa pasta.

Alternativamente, se colocou o arquivo no seu C:\ do Windows, digite no terminal do WSL2:

Terminal WSL2 
cp /mnt/c/koha_library.sql ~/koha_library.sql

Se você está no Servidor Físico, VPS ou VirtualBox (Cenários 1, 2 e 4):

Coloque o arquivo na raiz do disco local C:\ do Windows (ficando o caminho exato C:\koha_library.sql). Abra uma nova janela do PowerShell (sem estar conectado via SSH) e digite o comando abaixo (substitua nomedousuario pelo usuário criado no servidor e ipdoservidor pelo IP real da máquina):

PowerShell (Local) 
scp "C:\koha_library.sql" nomedousuario@ipdoservidor:/home/nomedousuario/

3. Executando a Restauração no Servidor

No terminal do Linux como root (sudo -i), execute este script. Ele recria a base de dados, importa o dump antigo, aplica correções de schema entre versões e reconstrói os índices do Elasticsearch:

script_restaurar_backup.sh 
#!/bin/bash
set -e

if [ "$EUID" -ne 0 ]; then
   echo "ERRO: Execute este script como root ('sudo -i')."
   exit 1
fi

BACKUP_FILE="${1:-/home/$SUDO_USER/koha_library.sql}"

if [ ! -f "$BACKUP_FILE" ]; then
   echo "ERRO: arquivo de backup não encontrado em: $BACKUP_FILE"
   echo "Uso: $0 /caminho/para/koha_library.sql"
   exit 1
fi

echo ">>> Backup encontrado: $BACKUP_FILE"

echo ">>> Recriando o banco de dados koha_library do zero..."
mysql -e "DROP DATABASE IF EXISTS koha_library; CREATE DATABASE koha_library;"

echo ">>> Restaurando o backup (isso pode demorar alguns minutos)..."
mysql koha_library < "$BACKUP_FILE"

echo ">>> Reiniciando memcached..."
systemctl restart memcached

echo ">>> Aplicando atualizações de schema (koha-upgrade-schema)..."
koha-upgrade-schema library

echo ">>> Reativando Elasticsearch nas preferências do sistema..."
mysql -e "INSERT INTO koha_library.systempreferences (variable, value, type) VALUES ('SearchEngine', 'Elasticsearch', 'Choice') ON DUPLICATE KEY UPDATE value='Elasticsearch';"
mysql -e "INSERT INTO koha_library.systempreferences (variable, value, type) VALUES ('ElasticsearchCommitImmediately', '1', 'YesNo') ON DUPLICATE KEY UPDATE value='1';"

echo ">>> Apagando índices antigos (se existirem) e reindexando do zero..."
curl -s -X DELETE 'localhost:9200/koha_library_biblios' >/dev/null 2>&1 || true
curl -s -X DELETE 'localhost:9200/koha_library_authorities' >/dev/null 2>&1 || true
koha-elasticsearch --rebuild -d library

echo ">>> Reiniciando serviços..."
systemctl restart koha-common
koha-plack --restart library

echo ">>> Verificando se o daemon de indexação está de pé..."
sleep 3
if ps aux | grep -v grep | grep -q es_indexer_daemon; then
   echo "OK: daemon es_indexer_daemon está rodando."
else
   echo "ATENÇÃO: o daemon não apareceu no ps aux. Confira:"
   echo "  journalctl -u koha-common -n 50 --no-pager | grep -A3 es-indexer"
fi

echo ""
echo "======================================================================"
echo " RESTAURAÇÃO CONCLUÍDA COM ELASTICSEARCH ATIVO."
echo " Teste buscando por um registro que existia no backup antigo."
echo "======================================================================"

7. Publicando o Koha na Internet (Cloudflare Tunnel)

O Cloudflare Tunnel é a forma mais segura de expor o Koha para a internet. Ele dispensa abertura de portas no modem ou roteador da biblioteca, oculta o IP real do servidor contra invasões e entrega certificado SSL (HTTPS) automático.

Passo 1: Domínio Institucional ou Subdomínio Gratuito

Para colocar o catálogo na web, é necessário um endereço de domínio:

  • Domínio Próprio (Recomendado): Registre um domínio institucional (ex: bibliotecamunicipal.org) diretamente no painel da Cloudflare (custo médio de R$ 50 a R$ 60 ao ano).
  • Subdomínio Gratuito (Custo Zero): Utilize um subdomínio gratuito no DigitalPlat seguindo o procedimento abaixo:
  1. Acesse domain.digitalplat.org e crie uma conta gratuita.
  2. No menu lateral esquerdo, clique em Register a domain e selecione Domain registration.
  3. Digite o nome escolhido para a biblioteca e escolha uma das 4 extensões disponíveis: .dpdns.org, .us.kg, .qzz.io ou .xx.kg.
  4. Clique em Check availability. Se o nome estiver disponível, a tela exibirá os campos de servidores de nome: Name Server 1 até 4. Mantenha essa página aberta.
  5. Em outra aba do navegador, entre no painel da Cloudflare e clique em Adicionar um site.
  6. Cole o nome completo do subdomínio criado no DigitalPlat (ex: bibliotecamunicipal.dpdns.org) e clique em continuar.
  7. Na tela de planos, role a página até o final, selecione o Plano Gratuito (Free) e continue.
  8. A Cloudflare fornecerá dois servidores de nome autoritativos (ex: ns1.cloudflare.com e ns2.cloudflare.com). Copie o primeiro endereço.
  9. Volte à aba do DigitalPlat, cole o primeiro endereço no campo Name Server 1 e o segundo no campo Name Server 2. Salve as alterações no DigitalPlat.
  10. De volta à Cloudflare, clique no botão Atualizei meus nameservers.
Tempo de Propagação do DNS: A delegação de nameservers em subdomínios gratuitos costuma levar entre 15 minutos e até 1 hora para propagar pela internet. Se a Cloudflare exibir um aviso informando que os servidores ainda não foram detectados, não exclua o domínio: aguarde alguns minutos e clique novamente em Verificar nameservers agora.

Passo 2: Criando o Túnel Cloudflare

  1. No painel lateral da Cloudflare, navegue até: Zero Trust > Networks > Tunnels.
  2. Clique em Add a tunnel, escolha a opção Cloudflare Managed e defina um nome de identificação (ex: koha-servidor).
  3. Na tela de instalação do conector, clique na opção Debian e selecione a arquitetura 64-bit.
  4. O painel exibirá dois comandos em um quadro preto:
    • O primeiro comando baixa o pacote oficial do conector cloudflared.
    • O segundo comando instala o serviço e vincula o token de autenticação exclusivo do túnel.
  5. Copie e execute ambos os comandos no terminal do Linux como root. O serviço iniciará de imediato em segundo plano.

Passo 3: Mapeando as Rotas do Staff e do OPAC

No painel do túnel, clique na aba Public Hostnames (Rotas de aplicativo publicadas). Você deve cadastrar duas rotas clicando no botão Add a public hostname:

Finalidade Subdomínio Domínio Caminho (Path) Tipo (Service) URL Local
Staff (Administração) adm Seu domínio cadastrado Deixe em branco HTTP localhost:8080
OPAC (Público / Leitor) Deixe em branco Seu domínio cadastrado Deixe em branco HTTP localhost:80

Com essa configuração, os bibliotecários acessarão o sistema por https://adm.seudominio.org e os leitores consultarão o catálogo por https://seudominio.org.

Passo 4: Blindagem contra Raspadores e Bots de IA

Catálogos públicos sofrem varreduras contínuas de robôs de treinamento de IA, gerando requisições em massa que podem sobrecarregar o Elasticsearch. Para proteger o servidor:

  • No painel da Cloudflare, abra as configurações do seu domínio e clique em Security > Bots.
  • Ative a chave Bot Fight Mode.
  • Na aba de segurança contra IA, ative a opção Bloquear bots de treinamento de IA (Block AI scrapers and crawlers).
  • Caso a biblioteca sofra lentidão repentina por tráfego incomum, ative temporariamente o Modo Sob Ataque (Under Attack Mode) na página inicial do domínio para exigir um desafio de segurança aos visitantes.

Passo 5: Indexação no Google e URLs Base do Koha

  1. Acesse o Google Search Console com sua conta institucional.
  2. Selecione o método de verificação por Prefixo de URL ou Domínio, insira o endereço do seu OPAC e copie o código TXT gerado pelo Google.
  3. No painel da Cloudflare, acesse DNS > Registros e clique em Adicionar registro:
    • Tipo: Escolha TXT
    • Nome: Digite @ (representa o domínio raiz).
    • Conteúdo: Cole o código gerado pelo Google e salve. Volte ao Google e confirme a propriedade.
  4. No painel Staff do Koha (como administrador), acesse: Administração do Koha > Preferências do Sistema:
    • Busque por OpacBaseUrl: Digite a URL HTTPS pública completa do catálogo (ex: https://bibliotecamunicipal.dpdns.org).
    • Busque por StaffBaseUrl: Digite a URL HTTPS pública completa da administração (ex: https://adm.bibliotecamunicipal.dpdns.org).
    • Busque por LibraryName: Insira o nome oficial da biblioteca que aparecerá nos títulos dos resultados de busca do Google.
    • Busque por OpacMetaRobots: Certifique-se de manter desativada qualquer opção que impeça robôs de busca (como noindex), permitindo a leitura e catalogação pelo Google.
